3. GÜN · API SÖZLEŞMESİORTAK STANDARTLAR

4. API Tasarım Kararları

Base URL

`/api` kökü ve çoğul kaynak adları.

Kimlik

JWT Bearer; yalnız login anonim.

Format

JSON, camelCase, ISO-8601 tarihler.

Standart cevap zarfı

{
  "success": true,
  "message": "Görev başarıyla oluşturuldu.",
  "data": { ... },
  "errors": []
}

HTTP durum kodları

KodKullanım
200 / 201 / 204Başarılı okuma / oluşturma / gövdesiz güncelleme
400Giriş doğrulama veya geçersiz istek
401 / 403Kimlik yok/geçersiz veya yetki yok
404Kayıt yok ya da güvenlik gereği görünmez
409İş kuralı/benzersizlik/durum geçişi çakışması
413Dosya boyutu sınırını aştı

Sayfalama ve sıralama

`pageNumber=1&pageSize=20&sort=dueDate:asc`; maksimum sayfa boyutu 100. Liste cevabı `items`, `pageNumber`, `pageSize`, `totalCount`, `totalPages` alanlarını içerir.

6. Taslak Şemalar

  • LoginRequest / LoginResponse: e-posta, parola, access token, süre ve kullanıcı özeti.
  • ProjectCreateRequest: ad, açıklama, başlangıç ve hedef bitiş tarihi.
  • TaskCreateRequest: proje, başlık, açıklama, atanan kişi, öncelik ve tarihler.
  • TaskStatusUpdateRequest: hedef durum; geçiş business katmanında doğrulanır.
  • Enumlar: ProjectStatus, TaskStatus ve TaskPriority string olarak sözleşmede gösterilir.

Sözleşme kuralı: Backend, React ve mobil ekip aynı `docs/api-contract-draft.yaml` dosyasını referans alır. Uygulama Swagger çıktısıyla ayrışırsa sözleşme aynı PR içinde güncellenir.
